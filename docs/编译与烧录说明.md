# 编译与烧录（自己动手版）

板子上的固件是 `firmware/step5_power_audio/`。以后改代码、重新烧，按这份来。

---

## 1. 最快路径：双击脚本

| 脚本 | 干什么 | 什么时候用 |
|---|---|---|
| `tools\build.bat` | **只编译**，不烧录 | 改完代码先跑它看有没有错 |
| `tools\flash.bat` | 编译 → 烧录 | 编译通过了，要刷进板子 |

默认烧到 **COM11**。端口不对就从命令行指定：

```
tools\flash.bat COM6
```

`flash.bat` 有个硬规矩：**编译失败绝不烧录** —— 否则会把 build 目录里那份**旧固件**刷进去，看起来"烧成功了"但代码没变，排查起来很坑。

## 3. 想用 Arduino IDE 图形界面

1. 打开 `firmware\step5_power_audio\step5_power_audio.ino`
   （同目录的 `.cpp` / `.h` 会被自动带进去，不用手动加）
2. 工具 → 开发板 → 选 **Waveshare ESP32-S3-Touch-AMOLED-1.8**
3. 工具 → 确认这两项：**USB CDC On Boot: Enabled**、**PSRAM: Enabled**
4. 端口选 COM11

⚠️ 两件事：

- **IDE 用的是它自己的编译缓存**（不在 `build\step5_pa\`），第一次会重建整个 ESP32 核心，**慢几分钟**，之后是增量。两套互不干扰。
- 如果报找不到库（`Arduino_GFX` / `ArduinoJson` / `Arduino_DriveBus`），去 **文件 → 首选项 → Sketchbook 位置**改成 `D:\DevTool\Arduino IDE\Project`，重启 IDE。

## 4. 改完代码怎么验证（不复位读串口）

烧完用这个脚本读板子状态，**不会复位板子**（`dtr=0/rts=0` 打开，RAM 里的历史都还在）：

```
python tools\tap_peek.py COM11 s
python tools\tap_peek.py COM11 xl      ← 倒最近 24 条事件（按键/PMU 留痕）
```

固件自带的串口命令：

| 命令 | 作用 |
|---|---|
| `s` | 状态一行：BLE / 触摸 / 电量 / 配额 / 堆 |
| `xl` | 倒事件环（按键有没有发出去，看这个） |
| `k <KEY> [act]` | 手动发一个 HID 键，例 `k ACT11 1` |
| `vc [ACTxx]` | 看/改 PWR 键发的键名（默认 `ACT11`） |
| `p` `e` `g` | PMU 遥测 / ES8311 寄存器回读 / 播提示音 |

## 5. 四个会浪费时间的坑

1. **端口独占。** 烧录前必须关掉：Arduino IDE 的串口监视器、Tabby、任何抓 COM 口的脚本（EInkInfo 的 `codex_bridge.py` 会每 5 秒扫一遍所有 USB 口）。症状是 `could not open port` / `访问被拒绝`。
2. **开串口 = 复位。** ESP32-S3 原生 USB 上，打开 COM 口的动作本身会复位板子（RTS 拉低 EN）。所以要读"上次开机以来"的东西，必须用 `tap_peek.py`（它不拉 RTS）。
3. **别删 `build\step5_pa\`。** 它是增量编译的基础，留着它改一次固件只要一两分钟；删了就要重建整个 ESP32 核心，多花好几分钟。其余 `build\*` 都是旧 step 的产物，可随时清。
4. **别升级 ESP32 核心。** 现在这套代码是在 **3.3.7-cn** 上验证过的（NimBLE 后端、Bluedroid 未启用）。升到 3.3.11 可能改 BLE / I2S 的行为，出问题不好定位。

## 6. 常见报错对照

| 报错 | 意思 |
|---|---|
| `could not open port COM11` | 端口被占，见坑 1 |
| `error: 'xxx' was not declared` | 用了变量但没在**使用点之前**定义（C++ 不向前找） |
| `Compilation error: exit status 1` | 往上翻找第一个 `error:` 行，后面那些都是连锁反应 |
| 编译过了但板子行为没变 | 确认走的是 `flash.bat`（它保证先编译），别单独跑 upload |
| 板子反复重启 | 可能开了 Serial Monitor 又开了别的抓口工具，两者互相拉 RTS |
